**Cause.** The reader looks in the sheet's bottom-right quarter for the number, then takes as a title only type at least 45% of the number's size. E1.3A's number is 37.4 pt, so the floor is 16.8 pt:

| Text | Size | Clears 16.8 pt? |
|---|---|---|
| HENDRICK HONDA / BRADENTON / GEN IV / RENOVATION | 24.9 pt | yes |
| FIRST FLOOR PLAN - / SALES - HVAC CONNECTIONS, just above the number | 12.5 pt | **no** |

So the project's name is the only candidate. Within a set the name repeats, becomes a "constant", and is refused; alone, or as a set's first sheets, nothing says it is the project's. The read then counts as **valid, so the AI
fallback never runs.** In the key's 26-sheet set the same sheet came out right.

**The fix I would make.** When no constants exist yet, prefer title type close to the number over larger type far from it: here the real title is 0.02 of the sheet's height from the number, the project name 0.3. That means
trying `_small_title`'s nearest-block search first, and treating a large block outside its reach as not a title. Measure it on the 103-sheet key before shipping; the risk is a nearby revision note or stamp being read as a title. The
smaller fix, sending a lone sheet with a far title block to the AI, costs credits on correct sheets.
